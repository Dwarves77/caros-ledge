# Caro's Ledge

Freight sustainability intelligence. This tree is the clean-room rebuild: a new repository, no history from the old one. It is building; `src/app/page.tsx` says so.

The plan is in `docs/BUILD-PLAN-2026-10-12.md`; how it is executed is in `docs/PART2-AGENT-PLAN-2026-10-15.md`. docs/WHY-2026-10-16.md is the operator's rationale: read it before any build or improvement decision; its section 7 is the decision procedure.

## Rules

1. Every feature of the old product is kept; each is written once, as the best version of itself.
2. Everything is free: no metered model API, no Browserless.
3. Hierarchy: `src/core` (substrate, at most 25,000 code lines), `src/features/<name>`, `src/ui`, `src/app` (thin routes). `src` at most 75,000 (raised from 60,000 by the operator on 2026-10-16 after wave 2 landed every feature at 100 to 163 percent of the plan budgets).
4. Every file under `src/` carries `// Ported from old_repo/<path> (lines a-b[, c-d])`, or is listed with a reason in its slice's allow-file `scripts/ci/new-files/<slice>.txt` (lines of `path | reason`). `tree-checks` validates every range against `scripts/ci/old-tree-lines.json` (line counts of every file under `fsi-app/` at old repo commit 646fb098c, `fsi-app/` prefix dropped, regenerated by `scripts/gen/old-tree-lines.mjs`). **Count lines the way `wc -l` does** (newline-terminated lines): a range ends at most at that count, and an unknown path fails. The check runs over the working tree, so an untracked file is checked locally exactly as on the PR.
   Merger note: if a merge brings a line into a retired `scripts/ci/new-files.txt`, move it into your slice's file under `scripts/ci/new-files/` and delete the old one. Route guards in `tests/core/structure.test.ts` are read from the tree; add no per-slice literal there.
5. A dependency needs a line in the `budget` block of `package.json`. No `@anthropic-ai/*`, `openai`, or Browserless.
6. The database is `supabase/schema.sql` plus forward files in `supabase/migrations/`, each ending in a DO-block self-check.
7. Facts live in the database; code and docs cite them and never restate them.
8. One workflow, `.github/workflows/ci.yml`. A red run is fixed at the root cause before any re-trigger.
9. Lint has zero warnings: no unused variables, no `any`, ordered imports, no console outside `src/core/shared/log.ts`.
10. No personal name, email or home path anywhere in the tree.

## Proofs (all in CI)

- `ci`: `npm run lint`, `typecheck`, `build`, `test`, `tree-checks`, `loc`.
- The `ci` job's last step posts or updates ONE PR comment (marker `<!-- ci-report -->`) with the run id, every job's conclusion and the loc table. Read it there; do not edit the PR body for it.
- `schema`: `supabase/schema.sql` applies to an empty Postgres 15 with zero errors (`npm run schema:apply`), then `scripts/ci/properties.mjs` runs: RLS on every table, no anon write policy, every foreign key indexed, every function's `search_path` pinned. The last two fail on the baseline and are waived in `scripts/ci/baseline-waivers.json` until the forward migrations land; the run prints the offenders under "KNOWN BASELINE FAILURES, forward migrations owed".

Edits to `supabase/schema.sql` against the production dump are recorded in `supabase/SCHEMA-NOTES.md`. Environment variable names are in `.env.example`.
