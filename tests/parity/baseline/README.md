## Capture contract (G1, G2)

The record capture.mjs writes has a version, `contract` in index.json (CAPTURE_CONTRACT in tests/parity/contract.mjs). Contract 2 records every list row (`[data-part="list-row"]`, `[data-part="table-row"]`) with its container, names a landmark by its aria-label, takes the page height from `<main>`, shoots the whole page, and carries `truncated` and the layout `offences` of the route. A baseline written under another contract is not compared: compare.mjs fails the run and names the recapture. Capture waits for the hydration marker (`data-hydrated`, src/ui/shell/Hydrated.tsx), so recapture only from a build that carries it. A deployed preview is behind Vercel deployment protection: the capture sends `x-vercel-protection-bypass` from VERCEL_AUTOMATION_BYPASS_SECRET to the captured origin only. 
## Recapturing the baseline

Counts and data-derived option sets drift (the compare gate treats integer runs in control and heading names as data), but the site's look and structure can also change, and a deliberate refresh is a PR of its own:

1. Dispatch the workflow `CI` (Actions, Run workflow) with input `only` = `baseline` (it then runs that job alone; with `only` empty a dispatch runs every job except `baseline`, and the `turn` job writes dry rows to the production ledger) and input `routes` (default `all`). Job `baseline` captures https://carosledge.com with the LIVE_SMOKE_* account and uploads artifact `parity-baseline-<run id>`. It never runs on push or pull_request.
2. Download the artifact; replace the files under `tests/parity/baseline` (keep PNGs only for the four signed-out routes, replace every e-mail address with smoke@example.invalid as above).
3. Update the capture date and the run id in this README, commit, open a PR. Compare then runs against the new baseline in the same PR's parity job.

The job passes `--site old` (a route with `oldPath` in routes.json is captured there; routes.json carries none now, so every route is captured at its `path`). Compare treats integer runs in names as data.

## Owed: recapture of home, login and signup (CTX-1)

PR 82 (560335e) changed the masthead title from Anton capitals to sentence-case sans bold, so the 1280x900 images of home, login and signup, shot before it, differ by about 2 percent by design. Home and login are at about 1.9% (with the capture clock pinned) and pass; until the three are recaptured the bounded pixel waiver `ctx1-title-type-signup` in approved-changes.json (with a `maxDiff` ceiling) carries signup. To retire them: dispatch `CI` with `only` = `baseline` and `routes` = `home,login,signup`, replace the six PNGs (both widths) from the artifact, update the date and run id above, delete the waiver (the report's `unused waivers:` line names it once the diff is back under 2 percent), and open a PR. The capture pins a signed-out page's clock to `CAPTURE_NOW` (contract.mjs, 2026-10-20 12:00 UTC), so the date and ISO week these pages print are the same in a recapture and in every later capture.
